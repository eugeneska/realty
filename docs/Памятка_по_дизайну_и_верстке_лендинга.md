# Памятка по дизайну и верстке лендинга

Главный принцип: **мы не придумываем новый сайт с нуля**.\
У нас уже есть:

- готовый черно-белый прототип со всеми текстами, смыслами и порядком блоков
- существующий сайт клиента, из которого мы берем визуальную систему

## 1. Сначала собираем дизайн-систему

Перед началом работы подключаем в проект **UI UX Pro Max**.

В него переносим визуальный стиль текущего сайта клиента:

- шрифты
- размеры и начертания текста
- основные и дополнительные цвета
- стили кнопок
- скругления
- стили карточек
- поля и формы
- отступы
- другие повторяющиеся элементы интерфейса

Итог: перед версткой у нас уже должна быть готовая дизайн-система, на которую дальше опирается весь лендинг.

## 2. Прототип не меняем

Черно-белый прототип является основой страницы.

Без согласования не меняем:

- тексты
- смысл блоков
- порядок блоков
- CTA
- структуру воронки

Задача дизайна — **красиво визуализировать уже готовый прототип**, а не перепридумывать его.

## 3. Для каждого блока ищем визуальный референс

Берем прототип и делаем отдельный скриншот каждого блока.

Скриншот отправляем в чат с ИИ и просим подобрать **поисковые запросы для поиска референсов именно под этот блок**.

Например:

Hero → отдельный запрос\
Кейсы → отдельный запрос\
Этапы работы → отдельный запрос\
Сравнение → отдельный запрос\
Отзывы → отдельный запрос

После этого по запросам находим несколько сильных референсов.

Важно: мы не копируем чужой сайт целиком. Берем у референса композицию, подачу информации, расположение элементов или интересный визуальный прием.

## 4. Референс сначала согласовываем

До начала дизайна каждого блока программист показывает выбранный референс мне.

После согласования можно переходить к реализации.

**Не нужно сначала делать весь блок, а потом показывать.**

Сначала:

**прототип → запрос → референс → согласование → дизайн**

## 5. Делаем сразу Desktop + Mobile

После согласования референса программист собирает блок на основе:

- структуры нашего прототипа
- согласованного референса
- дизайн-системы существующего сайта

Каждый блок сразу должен быть продуман в двух версиях:

**Desktop**\
**Mobile**

Мобильная версия не должна быть просто уменьшенной десктопной. Композицию можно адаптировать под удобное чтение с телефона.

## 6. После сборки — финальная проверка

Перед сдачей страницы проверяем:

- сохранены ли все тексты и смыслы прототипа
- сохранен ли визуальный стиль старого сайта
- одинаково ли используются цвета, кнопки, скругления и типографика
- нет ли блоков, которые визуально выбиваются из общей системы
- корректно ли выглядит Desktop
- корректно ли выглядит Mobile
- не потерялась ли конверсионная логика прототипа

### Коротко весь процесс

**Прототип → дизайн-система старого сайта → скриншот блока → запросы для референсов → поиск референса → согласование → Desktop + Mobile → проверка**
